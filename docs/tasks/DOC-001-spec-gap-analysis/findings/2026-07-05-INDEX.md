1. Pick a plan from the priority list (see [2026-07-05-INVESTIGATION-COMPLETE.md](2026-07-05-INVESTIGATION-COMPLETE.md))
2. Read the **Findings Document** (✅ complete) or expand the stub using the **Handoff Document**
3. Read the **Spec** (e.g., `docs/spec/export.md`)
4. Review 2-3 existing plans for structure (e.g., `2026-07-03-atlascloud-support.md`)
5. Create your plan following the template format

### To Expand a Stub Findings Document:
1. Use the corresponding **Handoff Document** as investigation guide
2. Follow the investigation checklist in the handoff
3. Use suggested grep/code_find patterns
4. Write detailed findings with file paths, line numbers, code snippets
5. Save back to the stub findings file

### To Verify Critical Bugs:
1. See **Critical Bugs Summary** (above)
2. Each bug has a file path and line numbers
3. Each bug is documented in its corresponding findings file
4. Each bug should become a high-priority task in its plan

## 📝 Writing the Plans

Each plan should include:
1. **Goal statement** (from findings)
2. **Current State vs Spec** table (from findings)
3. **Architecture/Tech Stack** overview
4. **File map** (files to create/modify)
5. **Numbered Tasks** (1–N):
   - Files affected
   - Steps (checklist `- [ ]`)
   - Code snippets
   - Verification commands
   - Git commit step
6. **Size/Complexity estimate** (S/M/L/XL)

**Format template:** Use existing plan file (e.g., `2026-07-03-atlascloud-support.md`)
